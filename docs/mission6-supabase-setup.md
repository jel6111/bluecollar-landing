# 미션 6 Supabase 준비

## 현재 자원

2026-10-21 새 무료 `practice` 조직에 클라우드 `bluecollar-mission6-demo`를 생성하고 연결했습니다. ref는 `uikvezrkmwplbslayene`이며 운영 프로젝트와 별개입니다. 마이그레이션 2개, 비공개 사진 버킷, 가상 예시 2건 준비 및 클라우드 DB/Storage 검사 7개·브라우저 검사 11개를 통과했습니다.

개발 당시 별도 로컬 스택도 보관합니다. API 56321, DB 56322, Studio 56323 전용 Docker 자원이며 기존 로컬 환경은 Git 제외 백업에 있습니다. 현재 코드의 등록 정보와 `.env.local`은 새 클라우드를 가리키므로 로컬 재사용 전 명시적으로 등록 모드와 환경을 함께 전환해야 합니다.

로컬 시작은 `npm run db:start`, 중지는 `npm run db:stop`입니다. 운영 프로젝트 이름을 입력하거나 전체 프로젝트를 조회하는 명령은 사용하지 않습니다. 사용자 인증 기능은 구현하지 않았고, Supabase의 기본 API 키 인프라만 로컬에 존재합니다.

로컬 SQL 갱신은 `npm run db:migrate`, 파일 정리 재시도는 `npm run cleanup:images`다. 비공개 버킷·내부 정리 테이블·가상 예시 2건까지 준비했다.

무료 한도 때문에 처음에는 로컬에서 개발했고 이후 사용자가 새 무료 조직을 준비해 클라우드로 연결했다. 운영 자원 재사용·중지·삭제나 유료 결제를 자동 실행하지 않는다.

## 새 클라우드 과제 프로젝트 연결

1. 사용자가 Supabase 대시보드에서 **새** `bluecollar-mission6-demo` 프로젝트를 생성한다. 기존 서비스 프로젝트를 열어 데이터·환경 변수·키를 복사하거나 수정하지 않는다.
2. 새 프로젝트 이름·생성 여부·project ref를 확인한다. 비밀이 아닌 ref만 연결 기록에 남긴다. 키/DB 비밀번호/토큰은 채팅에 보내지 않는다.
3. 새 프로젝트의 SQL Editor에서 저장소의 `supabase/migrations/20261014000100_create_work_records.sql`, `20261014000200_record_images.sql`을 순서대로 실행한다. 실행 직전 프로젝트 이름과 ref를 확인한다.
4. 미션 6 체크아웃의 비추적 `.env.local`을 새 과제 값으로 설정한다. 현재 로컬 값은 필요하면 별도로 보관하되 Git에 넣지 않는다.
5. 프로젝트를 명시적으로 등록한다.

```bash
npm run setup:demo -- 새프로젝트ref --new-demo-project
npm run check:db
```

등록 도구는 URL/ref 일치·미션 6 브랜치·제출용 origin을 검사한다. 새 ref를 생성 확인 없이 자동으로 URL에서 추출해 허용하지 않는다.

6. 브라우저 실제 데이터 테스트를 새 과제 프로젝트에서 다시 수행한다. 테스트는 생성한 UUID만 정리한다.
7. 이후 새 미션 6 Vercel에 동일한 새 과제 설정을 적용한다. 기존 서비스·미션 5 프로젝트의 환경 변수를 변경하지 않는다.

## 환경 변수 이름

```dotenv
SUPABASE_URL=
SUPABASE_SECRET_KEY=
NEXT_PUBLIC_SITE_URL=
```

서버 키는 실제 값을 Git·문서·브라우저·로그에 출력하지 않는다. 서버 전용이며 공개 키 접두사를 사용하지 않는다. 로컬 연결 설정은 Vercel에서 사용할 수 없도록 차단돼 있다.

## 연결 제한의 근거

초기에는 연결 도구와 브라우저가 준비되지 않아 별도 로컬 Supabase로 검증했다. 2026-10-21에는 사용자가 만든 새 과제 프로젝트만 브라우저에서 확인해 연결했다. 전체 프로젝트 목록이나 운영 프로젝트의 데이터·키는 조회하지 않았다. 코드가 확인된 과제 ref/URL만 허용하며 키는 서버 환경에 보관한다.
