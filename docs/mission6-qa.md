브라우저 검사는 설치된 시스템 Chrome과 로컬 앱/DB가 필요하다. 일반 재현은 README의 test/test:db/test:e2e 명령을 사용한다.

`npm run test:states -- empty`는 기본 가상 예시 상태에서만 실행한다. unavailable 검사는 별도 터미널의 앱 프로세스에 `SUPABASE_SECRET_KEY=qa-invalid-test-key`를 적용해 실행하고 다른 터미널에서 `npm run test:states -- unavailable`을 수행한다. .env.local은 수정하지 않는다. 검사 후 테스트 앱을 중지하고 정상 설정의 앱으로 복귀한다. 실행 위치·포트는 미션 6 전용이다.

DB/Storage는 원자적 트랜잭션이 아니다. 파일 정리 큐에 저장할 수 없을 정도로 DB가 끊기거나 프로세스가 중단된 경우 서버의 과제 UUID/경로 기록에 대한 후속 확인이 필요할 수 있다. 실제 API 키·원문 오류는 기록하지 않는다.

클라우드 Supabase·Vercel의 전체 QA, 실제 10분 경과 URL 만료, 배포 환경 평가자 접근은 4묶음에서 확인한다. 개발 도구 의존성의 기존 high 9건도 남아 있다. 운영 서비스·미션 5 배포·main은 변경하지 않았다.
