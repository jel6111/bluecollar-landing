## 구현 후 확인

`npm run lint`, `npm run build`, 브라우저 전체 흐름, 과제 Supabase의 테스트 UUID/파일 저장·삭제를 확인한다. 1묶음 문서·설정 검증을 CRUD 테스트 통과로 표시하지 않는다. 다음 묶음에서 핵심 서버 검증과 실패 보상에 필요한 테스트를 추가한다.

## 2묶음 검증 근거

- `npm run lint`: 통과.
- `npm test`: 입력·달력 날짜·UUID·페이지·다른 DB 주소 차단·미등록 프로젝트·로컬 배포 차단 8개 통과.
- `npm run build`: Next.js 16.4.0 빌드 통과, `/records`, `/records/new`, `/records/[id]`는 요청 시점 렌더링.
- `npm run test:e2e`: 실제 로컬 Supabase를 사용한 브라우저 검사 5개 통과. 최종 빌드의 `next start`에서도 5개 통과. Mock API나 localStorage를 사용하지 않음.
- 데스크톱 목록과 모바일 등록·상세의 스크린샷을 직접 확인함. 화면 겹침·잘림 없음.
- Git 대상 후보 파일 72개와 브라우저 정적 청크 16개에서 새 로컬 비밀 키·키 형식이 없음을 검사함. `.env.local`과 Supabase 임시 설정은 Git 제외 확인.
- 새 로컬 DB에서 RLS=true, anon SELECT=false/INSERT=false, service_role INSERT=true 확인.
- 테스트 생성 UUID만 정리했고 개인정보 없는 가상 예시 1건을 따로 준비함.
- `npm audit --omit=dev`: 0건. 전체 감사의 개발 도구 의존성 9개 high는 남아 있으며 강제 메이저 다운그레이드는 적용하지 않음.
- 클라우드 Supabase와 Vercel에 대한 통과 결과는 없음. 수정·삭제·Storage 업로드는 3묶음에서 검증해야 함.
