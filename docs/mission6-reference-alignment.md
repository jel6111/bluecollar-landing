# 제품 자료를 반영한 화면 보정

문서 반영: 2026-10-16. 화면 구현/DB·브라우저 검증: 2026-10-14.

사용자가 제공한 제품 설명·디자인 원칙·소스/시험 코드 발췌를 참고했다. 실제 서비스의 현재 배포 상태를 조회한 결과가 아니다. 제공 자료의 운영 명령·자격 증명·원문·DB 구조를 실행하거나 그대로 복제하지 않았다.

## 반영 결정

| 항목 | 과제 구현 |
|---|---|
| 핵심 가치 | 현장 사진을 설명과 함께 남기고 다시 찾아 활용 |
| 랜딩 | 문제 → 제품 사용 흐름 → 기대효과 → 과제 체험 CTA |
| 입력 | 사진 → 현장 이름 → 짧은 설명. 자주 쓰는 문구 버튼 |
| 제목 | 추가 입력. 생략하면 설명 첫 줄(최대 120자) 또는 현장 이름으로 보충 |
| 날짜 | 직접 선택한 work_date와 DB created_at 등록일 구분. 목록은 등록일·생성순 |
| 용어 | 기록 관리·사진 추가·기록 열기·고치기 |
| 사진 | 목록은 정사각 썸네일과 설명. 상세는 사진을 설명 앞에 잘리지 않게 표시 |
| 디자인 | 흰 배경·blue #2563EB·slate 본문·Pretendard·44px 이상 터치 영역 |
| 데이터 | 가상의 현장/설명/코드 생성 사진. 운영 자료를 DB로 수집하지 않음 |

## 날짜의 의미

work_date는 직접 고르는 **참고 날짜**다. 기존 컬럼을 재사용하며 실제 일한 날로 간주하지 않는다. created_at은 DB의 **기록 등록 시각**이고 한국 시간으로 등록일을 표시한다. 사진 교체 후에도 원래 기록 등록일은 유지한다.

촬영일·사진 수신일·직접 확인한 근무일·예정 일정은 다른 정보다. 과제에서는 자동 추정하지 않는다. EXIF를 제거하므로 사진 촬영 시각을 확인했다고 표현하지 않는다.

## 소개와 체험 범위

제품 소개는 카톡 사진 전송 → 현장/받은 날별 기록 관리 → 보고 링크/PDF → 보관함·직접 선택한 포트폴리오 흐름이다. 자료의 일정 기능은 사진 기록 CRUD 범위에 추가하지 않았다.

체험 기능은 웹 기록 1건의 등록·목록·상세·수정·삭제와 선택 사진 1장의 업로드·교체·제거다. 모든 CTA는 과제 내부 경로다. 로그인과 개인별 권한은 미션 7 범위다.

오래된 디자인 문서와 제공 코드의 차이는 역할에 맞춰 해석했다. 모든 사진에 3:4를 강제하지 않고 기록 목록에는 정사각 썸네일을 사용한다. 아이콘은 과제의 기존 Lucide 라인 아이콘을 유지한다. 고객 성과·시간 절약 실측·이용자 수·수익을 만들어 쓰지 않는다.
